# 产品说明（PRODUCT_SPEC）

## 定位

Sucremi 是**个人开发工作台**。核心解决的问题：项目中断一段时间后，重新捡起时忘记了

- **进度**：做到哪一步了；
- **设计原因**：当时为什么这么选；
- **资料位置**：相关链接、文档、片段放在哪；
- **下一步行动**：接下来该做什么。

## 范围与阶段

- 第一版（V1）只服务**单个用户**，优先建设**私人工作台**。
- 公开网站（对外展示 / 博客等）后续阶段再做。
- 不在早期实现：AI、多 Agent、公开博客、复杂权限。

## 已完成

### 阶段 0 —— 工程初始化

1. 前后端工程骨架可独立安装、构建、启动。
2. 统一 API 响应结构与全局异常处理。
3. 健康检查接口 `/api/v1/health`。
4. MySQL + Flyway 本地可用，首个迁移可执行。
5. 前端开发代理可访问后端。
6. 完整开发文档与本地启动/测试说明。
7. 至少各一组可运行的前后端测试。

### 阶段 1 / P0 —— 基础工作台 MVP

先把「项目」这个容器立起来，作为后续所有「防遗忘」记录的挂载点：

- 身份与数据归属：`CurrentUserResolver` 抽象 + 开发期固定身份 + 失败关闭兜底
  （决策记录 `docs/decisions/0001-identity-and-data-ownership.md`）。
- 项目模块：列表（分页 / 状态 / 归档过滤）、详情、创建、编辑、归档 / 取消归档。
- 概览统计：各类状态计数 + 最近更新的项目。
- 前端概览 / 项目列表 / 项目详情三个页面。

「防遗忘」四问目前只在**项目**这一层得到部分回答（做到哪一步、大致目标）。进度时间线、
检查点、设计决策记录、资料归集、下一步行动清单尚未实现 —— 项目详情页上对应的卡片均为占位。

## 后续方向（非承诺，详见 ROADMAP）

阶段 2 围绕「防遗忘」四问补上对应记录：任务与下一步行动、进度 / 活动时间线、检查点历史、
设计决策记录、资料归集。更远的多用户与权限、公开网站、AI 辅助在需求明确前不动工。
